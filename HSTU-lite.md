# HSTU-lite

Архитектура из рабочего `sol.md`: Transformer истории, два блока внимания
к истории для каждого кандидата и два слоя внимания между кандидатами ленты.
Совпадения объявления и категории влияют на внимание. Позиция показа доступна
только при обучении варианта с поправкой. Контроль использует ту же архитектуру
и тот же протокол без поправки. Оптимизация: softmax + 0,3 LambdaRank, EMA.

| Опыт | Данные | Устройство | Бюджет | Результат |
| --- | --- | --- | --- | --- |
| EXP-HSTU-001 CPU smoke | 24 591 лента train | CPU | 20 шагов на вариант | 0,285573 у обеих версий на 192 лентах |
| EXP-HSTU-001 GPU pilot | 4 равномерно выбранных шарда train | RTX 3060 Ti | 20 → 200 → 800 шагов | Запланирован |

Пилот фиксирует 2 000 лент первого дня val для выбора checkpoint. Поздние
ленты остаются отложенными. CPU smoke проверяет техническую работоспособность
на реальных данных. Для вывода о качестве нужна более длинная серия.

Запуск из корня ветки с существующим окружением PyTorch и PyArrow:

```powershell
python scripts/run_hstu_pilot.py --data Q:/AVITOCUP/competition --output Q:/AVITOCUP/experiments/EXP-HSTU-001 --device cuda
```

Состояние, лог и checkpoints находятся в `work/`. `last.pt` хранит модель,
optimizer, EMA, RNG, прогресс и время. `work/STOP_AFTER_CHECKPOINT` просит
паузу. Повтор команды с теми же параметрами после снятия маркера продолжает
эксперимент. Задача Планировщика `AvitoHSTULite001` публикует статус в
[общем мониторе](http://server.taild49777.ts.net:8787/).

Следующие этапы из `sol.md` — расширить train и повторить seed, затем проверить
финалистов на позднем holdout. Модули `feats`, `gbdt` и `blend` содержат
перенесённый код для отдельного эксперимента со стеком. Этим модулям нужны
pandas, Numba и LightGBM. NN-2 и meta-GBDT обучаются на val только в отделённом
протоколе с группировкой по пользователю. Их OOF служит для разработки ансамбля.
Подбор константы позиции и числа итераций использует раннюю часть val.
Признаки из будущих историй отключены. Отправка остаётся ручной.
