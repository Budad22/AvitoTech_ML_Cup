## EXP-TABNET-001 — другая архитектура на входах сильной MLP

- Гипотеза: последовательные маски признаков TabNet улучшают ранжирование
  на уже полезных входах MLP. Прирост неизвестен.
- Контроль: matched MLP + history + PLR + softmax, обученная на той же когорте,
  с теми же входными преобразованиями, seed и порядком целых лент.
- Изменение: заменить MLP backbone на TabNet, сохранив PLR f1–f5,
  категориальное представление, векторные входы, статистики истории и loss.
  Оба варианта обучать с нуля; веса MLP не являются готовыми весами TabNet.
- Использовать PyTorch-модуль внутри whole-feed trainer, а не стандартный
  построчный fit классификатора. Выход — один logit на кандидата;
  loss — softmax внутри ленты с равным весом лент плюс явно записанная
  регуляризация масок TabNet. Target/pos/ID не входят в признаки.
- Стартовая конфигурация для обсуждения: n_d=n_a=32, n_steps=3, gamma=1,3,
  sparsemax. Перед запуском отдельно фиксируются optimizer/LR, lambda_sparse,
  virtual_batch_size, фактический ресурс и критерий достаточного обучения.
  Это стартовая гипотеза, не подобранная конфигурация.
- Первый бюджет: одна matched пара seed42 на train4, общий лимит шагов/данных
  и явный предел времени; конкретный бюджет утвердить в карточке до запуска.
  Упор в технический предел отметить, не считать отрицательным результатом.
- Продвигать при delta selection NDCG >= +0,001 к matched контролю;
  перспективный вариант повторить на seed43/44 и большей когорте.

## EXP-TABNET-002 — групповые маски связанных признаков

- Гипотеза: раздельная селекция множества коррелированных координат может
  уступать вниманию к заранее определённым группам признаков.
- Контроль: конфигурация EXP-TABNET-001. Изменяется только группировка attention.
- Кандидатные группы: каждый PLR-вектор отдельного f, category embedding,
  user/item-векторы, их произведения/разности, блоки статистик истории.
  Точное разбиение и нормировка групп фиксируются до обучения без val-меток;
  крупные неделимые группы могут скрыть полезные различия координат.
- Один дополнительный seed42-опыт при работоспособном EXP-TABNET-001;
  тот же бюджет/протокол, порог delta >= +0,001. Все попытки сохраняются.
- Механизм группировки поддержан PyTorch-реализацией, полезность именно
  такого разбиения для наших признаков не измерена.

## EXP-TABNET-003 — дополнительность к сохранённой MLP

- Гипотеза: TabNet может улучшить ансамбль даже без победы по одиночному NDCG.
- Только после получения фактических val-score: проверить точные ключи,
  float32/конечность/границу и происхождение обоих checkpoint.
- Один заранее фиксированный кандидат: 50/50 per-feed z-score TabNet/MLP.
  Сравнить с более сильным одиночным родителем на selection; порог +0,001.
  Позднюю/полную val оценить после заморозки решения. Не подбирать веса по сайту.
- Оценивать также относительно сохранённого действующего ансамбля отдельно;
  победа над слабым одиночным контролем не означает нового лучшего решения.
- Бюджет: одна проверка сохранённых прогнозов, без переобучения родителей.

## EXP-TABNET-004 — функция потерь для ранжирования (идея)

- Контроль: лучший принятый TabNet с listwise softmax. Изменять только loss.
- Кандидат: pairwise logistic с весом по абсолютному изменению полного NDCG
  при обмене positive/negative внутри одной ленты. Пары сэмплировать по
  фиксированному seed, нормировать вклад внутри ленты, затем усреднять ленты.
  Не переходить на @10/@30 и не смешивать примеры разных лент.
- Ожидаемый эффект неизвестен; сравнение имеет смысл после работоспособной
  базы. Нужны отдельная реализация, ручные проверки весов/ничьих и карточка
  бюджета до запуска. Не реализовано и не запускалось.
- BCE с равным весом лент можно использовать как отдельный контроль, если
  нужно диагностировать softmax; это не разрешение на широкий перебор.

## EXP-TABNET-005 — self-supervised pretraining (низкий приоритет, идея)

- Гипотеза: реконструкция замаскированных признаков train перед supervised
  ranking помогает TabNet на этой задаче. Полезность здесь не измерена.
- Предобучение и fitted transforms только на train; не читать test и не
  использовать val для обучения. Затем fine-tuning с прежним ranking-loss.
- Для честной проверки архитектура encoder/группы/входы должны совпадать
  с supervised контролем, бюджет предобучения учитывается отдельно.
  При обучаемом PLR/category front-end заранее определить фиксированные
  реконструируемые цели и корректный перенос весов; простой вызов стандартного
  TabNetPretrainer не равен готовому переносу в наш low-level ranker.
- Один условный опыт после сильной supervised базы и проверки групповых масок;
  до отдельной карточки бюджета не реализовывать/не запускать.
- Источник механизма: https://arxiv.org/abs/1908.07442 и
  https://github.com/dreamquark-ai/tabnet . Это поддержка метода, не гарантия роста.
