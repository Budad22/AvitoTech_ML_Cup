## Forward одной ленты

Батч состоит из B целых лент, M и H — максимальные в батче числа реальных кандидатов и событий. Маски валидности строить из offsets. Пустая история допустима. Везде ниже ширина модели 128, четыре головы по 32, dropout 0.1, pre-LayerNorm, GELU, FFN 128→256→128. Сначала int8-векторы переводить в float32, затем L2-нормировать с eps 1e-12. При idx=-1 подставлять нулевой вектор и признак пропуска. Нулевой user-вектор получает свою маску.

1. Событие — item128, флаг пропуска, category embedding16, type8, source8, embedding порядкового номера по давности16. Конкатенация 177→128 линейно. Таблицы category/type/source имеют 54/11/31 строк, индекс 0 для неизвестного. Category embedding общий у обоих блоков. История от новых событий к старым, номера 0..255. Перед событиями добавить отдельный обучаемый токен [HIST], всегда валидный. Два двунаправленных encoder-слоя и финальная LayerNorm. Получаем [B,H+1,128] один раз на ленту.
2. Кандидат — user128, item128, произведение128, cosine1, category16, f1..f5, их пять процентилей внутри реальной ленты, два признака пропуска (item и нулевой user). Итого 413. Процентили считать как (число меньших + 0.5 × число равных)/M_real, с тем же соглашением, что в catboost/feed_context.py. MLP 413→256→128 с GELU и dropout между слоями формирует q. Для бинарных признаков использовать float32.
3. Cross-attention. Запрос берётся из LayerNorm(q), K/V из представлений истории. К QKᵀ/√32 добавить для каждой головы две обучаемые скалярные поправки с начальным значением 0. Первая включается при равенстве положительных исходных item_id, вторая при равенстве положительных исходных категорий. Эти сравнения работают и при пропущенном векторе. Для [HIST] обе поправки 0. Ключам padding поставить −∞ до softmax. Оставить [HIST] доступным даже при H=0. Выход четырёх голов спроецировать, применить dropout и прибавить к q.
4. Один encoder-слой self-attention по кандидатам, без позиций кандидата или причинной маски, с маской ключей padding. Финальная LayerNorm и общая голова 128→64→1 с GELU. Выход — сырые float32 scores. Padded строки исключить из потерь и метрик. Передавать labels и pos только функции обучения. ID использовать лишь для сравнений и выравнивания.

## Две стадии и контроль

Настройки v1, выбранные для первого воспроизводимого опыта. Seed 42, AdamW с weight_decay 1e-4, постоянный lr каждой стадии, FP32, эффективный batch 32 целые ленты. Номинальный microbatch 8. При нехватке VRAM уменьшать до 4/2/1 с накоплением градиента. Для эквивалентного среднего суммировать потери по лентам микробатча и делить на реальное число лент в текущем optimizer step. Сохранять все ленты, включая хвост. На каждой эпохе детерминированно перемешивать feed indices. Сохранять seed, текущую перестановку или её генератор, курсор, веса, optimizer и RNG CPU/CUDA на границе optimizer step, атомарно каждые 100 шагов и в конце эпохи.

- A. Пять эпох полного train, lr 3e-4. Скалярная таблица b с нулевой инициализацией индексируется исходным pos с 0 и с сохранением пропусков в нумерации. Размер max_train_pos+1, проверять диапазон. Для каждого кандидата BCEWithLogits(score+b[pos], y), затем среднее по кандидатам каждой ленты и среднее по лентам. При оценке возвращать score. Bias моделирует связь позиции с действием, причинная коррекция показов не доказана. Заморозить и сохранить последний checkpoint A.
- B. Инициализировать из A, заново создать AdamW, lr 3e-5, один полный проход по 7581 размеченной ленте, 237 optimizer steps при batch32. Этот бюджет фиксируется заранее. Ранги считать по отсоединённым от графа scores внутри ленты, при ties использовать пессимистический порядок официальной метрики и item_id для равных меток. Считать все пары положительный i / отрицательный j. Вес abs(d(rank_i)−d(rank_j))/IDCG, где ранг начинается с 1 и d(r)=1/log2(r+1). Потеря пары weight × softplus(score_j−score_i). Делить сумму по парам на число пар, затем усреднять по лентам. У ленты без пар вклад в loss нулевой. Сохранять checkpoint B на последнем шаге. Обучать все веса ранжировщика.
- После фиксации A и B получить на одних и тех же 6488 лентах scores трёх checkpoint — официальный EXP-TRF-002/best.pt, A и B. Точный путь контроля runs/EXP-TRF-002-r01/best.pt внутри EXP-TRF-002-r01, SHA e64954d8704843d7d490c26bd1f0c7d8437e76fed48405b0589f1742e4fdfe11. Загрузить его модель с исходным category_mapping из compact metadata и адаптером native features на этих лентах, с его обычным float32 sigmoid. Сохранённая метрика 0.354775 относится к другой когорте. Выбранный ранее checkpoint 002 видел историческую selection при выборе эпохи, часть дня 24 туда входила. Сравнение обозначить историческим.
- Основное сравнение B−002, дополнительные A−002 и B−A. Считать полный NDCG с одинаковым весом лент, при отсутствии positives значение 1. Проверить покрытие ключей и сверить NumPy с CatBoost evaluator. Для 95% интервала выбрать пользователей с возвращением 10 000 раз (seed 42), переносить все ленты выбранного пользователя с кратностью, каждый раз считать среднее парных разностей по лентам.
