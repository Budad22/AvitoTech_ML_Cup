# Автономная очередь MLP на 12 часов с резервом

**Обновление по новому указанию владельца:** действующее окно EXP-032 теперь
18 активных часов, максимальный защитный предел20ч. Прежние12/18 ниже —
история исходного плана. Независимый supervisor перезапускает аварийный процесс
с checkpoint, проверяет зависание по heartbeat и не создаёт дубли. Контролируемая
пауза/завершение уважаются. После трёх повторов одной ошибки требуется разбор,
а не бесконечные рестарты. Дополнительные разные seed поддерживают запас работы.

Запрос владельца: 18 ноября 2026 года, занять ближайшее окно полезными обучениями
и подготовить дополнительные задачи. Ветка `MLP`. Серия **EXP-032**,
каталог сервера `Q:/AVITOCUP/experiments/MLP-OVERNIGHT-GPU-032`.

## Окно и порядок

Текущая EXP-031 продолжает работу в неизменном снимке. Новый отсоединённый
контроллер ждёт реального завершения её процесса и освобождения GPU. Его
ожидание не расходует активный бюджет. Таким образом, ближайшие 12 часов
покрыты действующей EXP-031 и её продолжением; EXP-032 дополнительно получает
не менее 12 часов активной работы с защитным пределом 18 часов.

Длительности ниже — распределение бюджета, а не обещание ETA. Обучение
включает подготовку батчей, проверку качества и сохранение checkpoint:
непрерывные 100% GPU и отсутствие коротких промежутков валидации не обещаются.

| Порядок | Работа | Бюджет и правило |
| --- | --- | --- |
| 0 | Дождаться EXP-031, выполнить CUDA preflight | Ждать без конкуренции за GPU; старую очередь не перезапускать |
| 1 | PLR+softmax на полном train | До 2 ч, batch64, CPU-prefetch; приоритет подтверждённому победителю EXP-030 |
| 2 | 26 новых вариантов на готовом среднем наборе | Каждый до800 шагов, seed42; данные примерно1,56%, все кандидаты ленты |
| 3 | По одному лидеру каждой семьи + медленная длинная история | До3200 шагов суммарно, до10 вариантов; отбор только по fast |
| 4 | Шесть финалистов | До12800 шагов на seed42/43, продолжение optimizer/RNG |
| 5 | Победитель EXP-031, если отличается от PLR+softmax | До2 ч полного train по новой batch64/prefetch схеме |
| 6 | Два лучших новых варианта | До2 ч полного train каждому, seed42 |
| 7 | PLR+softmax seed43 и резерв различных моделей/seed | Последовательно до заполнения12 ч активного окна; закончить текущую модель после границы |
| 8 | Зафиксированные прогнозы на confirmation, итоговые отчёты | Решения/ранжирование уже заморожены; test не используется |

Есть запас из разных новых архитектур и seed43/44, существенно превышающий
12 часов при двухчасовых полных запусках. Верхний предел всей серии18 часов
защищает от зависания; это не требование обязательно потратить18 часов.
Одна комбинация модели/seed на full повторно не запускается в другой стадии.
При OOM/неконечных градиентах конкретный вариант сохраняет traceback и
исключается; очередь переходит к следующему, сбой не считается проигрышем.

Полный запуск имеет верхнюю границу12 эпох и2 часа активного времени.
Чаще сработает временной предел. В отчёте записываются реальное число шагов,
лент, эпох и `partial_budget`; название full не означает, что эпоха завершена.
Лучший checkpoint выбирается по fast NDCG, последний сохраняется для resume.
При отсутствии улучшения шесть проверок подряд модель можно остановить раньше,
но только после первого полного прохода train. Тогда бюджет переходит следующей
гипотезе; прекращение после крошечной доли первой эпохи не выдаётся за плато.

Полные эксперименты здесь являются ограниченными разведочными проверками
масштабирования: владелец отдельно разрешил больший бюджет и сильные гипотезы
на полном train. Порог EXP-031 не подменяется задним числом; новая серия имеет
собственный протокол. Малое преимущество не объявляется подтверждённым.

## Новые гипотезы

Все варианты сохраняют сильный путь PLR+статистики истории. Новые обучаемые
ветви добавляют поправку, а не удаляют уже полезные признаки. Это отдельные
опыты поверх общей базы, а не повтор44 конфигураций EXP-029.

| ID | Конфигурация | Смысл |
| --- | --- | --- |
| EXP-032-H01 | memory_multi4 | Четыре представления интересов под текущего кандидата |
| H02 | memory_multi8 | Восемь представлений интересов |
| H03 | memory_cosine | Прямое cosine-сходство направляет обучаемое внимание |
| H04 | memory_top8 | Внимание только к восьми ближайшим событиям |
| H05 | memory_top32 | Внимание к32 ближайшим событиям |
| H06 | memory_type4 | Тип события отдельно управляет каждой группой интересов |
| H07 | memory_no_order | Проверка необходимости порядковой давности при том же attention |
| H08 | memory_256 | Несколько интересов по всей доступной истории256 |
| H09 | memory_recent32 | Несколько интересов только по32 последним событиям |
| H10 | memory_dual | Разные головы для последних32 и более старых событий |
| H11 | experts_4 | Четыре эксперта, выбор смеси по истории пользователя |
| H12 | rankone_4 | Четыре ветви с общими весами и небольшими rank-one адаптерами |
| H13 | experts_8 | Восемь экспертов |
| H14 | rankone_8 | Восемь ветвей экономного ансамбля |
| H15 | bilinear_32 | Обучаемое билинейное взаимодействие user/item,32 компоненты |
| H16 | bilinear_64 | То же,64 компоненты |
| H17 | group_dropout | Регуляризация целых групп плотных признаков |
| H18 | memory_dropout | Регуляризация событий в обучаемой памяти |
| H19 | objective_smooth | Listwise softmax со сглаживанием целевого распределения |
| H20 | objective_temperature | Другая температура listwise softmax |
| H21 | objective_pairwise | Стабильный попарный softplus с равным весом лент |
| H22 | objective_pairwise_mix | Softmax + небольшая попарная добавка |
| H23 | objective_focal | Focal objective с равным весом лент |
| H24 | position_nuisance | Отдельная train-only поправка на позицию; на инференсе только релевантность |
| H25 | warmup_cosine | Разогрев и cosine-расписание learning rate |
| H26 | all_scalars_softmax | PLR кодирует также17 числовых статистик истории при softmax loss |

Rank-one ветви — собственный исследовательский вариант, не заявление о точном
воспроизведении TabM. Поправка позиции — проверяемая гипотеза,
не доказанное устранение bias: привлекательность и видимость смешаны.
Обратный CTR по позициям не применяется. Позиция не нужна при инференсе.

## Данные и честность сравнения

- Исходные prepared-full-v2 и все checkpoint EXP-031 остаются неизменными.
  Средний кеш и sequence-кеш переиспользуются только после выхода прежнего writer.
- Для новой позиционной ветви отдельно готовятся train-only buckets с точным
  сопоставлением feed_id и числа кандидатов. В val этих входов нет.
- Fast2000 и confirmation9534 относятся к прежней selection; историческая val
  не становится свежим holdout. Полный NDCG — по целым лентам, не @10/@30.
- Отбор семейств и шести финалистов — только fast; ранжирование по одинаковым
  seed42/43 замораживается до новой confirmation-проверки. Много сравнений и
  два seed не доказывают универсального превосходства архитектуры.
- Full batch64 отличается от прежнего batch16 и использует предвыборку CPU.
  Это отдельный протокол масштабирования; сравниваются реальные просмотренные
  ленты и время, а не одинаковые номера optimizer steps разных batch size.
- Предыдущие готовые baseline-результаты служат ориентирами. Повтор старой
  идентичной полной history_stats не запланирован.
- Предикты test, submission и отправка на сайт в очередь не входят.

## Автономность и просмотр

Контроллер — скрытый независимый WMI-процесс с OS-lock от дублей и защитой
от сна. Исчезновение SSH/чата не прекращает работу. Замороженный снимок кода,
source.json, status.json, ledger.json, события и traceback остаются на SSD.
Возобновление использует веса, optimizer/RNG и потраченное активное время.

```powershell
python scripts/remote.py status --host 26.27.122.189 --user bl1tz2200 --logs
python scripts/remote.py status --host 26.27.122.189 --user bl1tz2200 --watch 2
```

Пока EXP-031 работает, команда показывает её и наличие следующей очереди.
После освобождения GPU активная очередь автоматически переключится на EXP-032.
Ctrl+C закрывает просмотр. Итог — status=completed и report.json; завершение
одного двухчасового опыта не означает завершения всей серии.
