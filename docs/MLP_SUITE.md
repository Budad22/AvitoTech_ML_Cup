# Автономная очередь MLP

`MLP-SUITE-001` выполняет 11 независимых обучений последовательно на RTX 3060 Ti.
Код фиксируется отдельным снимком на SSD Q:, входы `prepared-full-v2` доступны
только для чтения. Прежние веса EXP-013-r02 сохраняются.

## Порядок и сравнение

| Вариант | Изменение относительно контроля |
| --- | --- |
| baseline | Прежняя MLP, BCE с равным весом лент |
| history_stats | Окна 8/32/128, сходство векторов, категории, частоты кодов событий |
| history_pool | Обучаемое усреднение последних 64 событий |
| history_attention | MLP-внимание к тем же 64 событиям для каждого кандидата |
| softmax | Listwise softmax с нормировкой по положительным кандидатам |
| lambda | Парная logistic loss с весами изменения полного NDCG |
| context_stats | Ранги, отклонения f1–f5, доли категорий, размер ленты |
| context_pool | Те же статистики и обучаемый mean/max-контекст кандидатов |
| cross | Проекции user/item и два cross-слоя ранга 64 параллельно MLP |
| raw_norm | log1p-нормы исходных user/item-векторов |
| low_lr | Прежняя MLP с learning rate 0.0003 вместо 0.001 |

Каждый вариант начинает обучение заново: seed 42, batch 64, AdamW,
до пяти эпох, до двух часов с учётом промежуточной валидации, patience 2.
По достижении бюджета текущий checkpoint оценивается на selection.
Бюджет — ограничение, не прогноз длительности. Частичные эпохи отмечаются в отчёте.
Наиболее прямые сравнения: baseline/softmax/lambda/low_lr,
history_pool/history_attention и context_stats/context_pool.

Выбор checkpoint и общего победителя использует только ранние 80% val (selection).
Поздний control и полный val оцениваются у одного выбранного победителя.
Для него автоматически готовится и проверяется `submission-winner.parquet`.
Отправки на сайт в коде нет.

## Запуск и восстановление

Перед запуском выполнить `scripts/run_gpu_suite.ps1 -CheckOnly` в замороженном
снимке: все unittest и синтетический CUDA forward/backward/optimizer step для
всех вариантов при 64 лентах × 300 кандидатах. Это проверка ресурсов, не обучение
на соревновании. Затем запускать этот скрипт без `-CheckOnly` через задачу
Windows `AvitoMLPSuite` (S4U, unlimited execution, IgnoreNew).

Очередь продолжает работу без CLI/SSH. Checkpoint сохраняется каждые пять минут
и после эпохи; повторный запуск восстанавливает optimizer, RNG и курсор.
Файловая блокировка исключает второй контроллер; после сбоя контроллера он сначала
дожидается оставшегося дочернего процесса. Ошибка одного опыта записывается,
следующий вариант запускается автоматически. Сбой финальной оценки допускает
повторный запуск без повторения уже завершённых обучений.

`STOP_AFTER_CASE` в каталоге очереди приостанавливает её между опытами;
`STOP_AFTER_CHECKPOINT` в каталоге конкретного запуска сохраняет и приостанавливает
текущий опыт. Для продолжения убрать флаг и повторно запустить задачу.

## Проверка состояния

Из локального репозитория:

```powershell
.\.venv\Scripts\python.exe scripts/remote.py suite-status --host 25.9.106.39 --user bl1tz2200
.\.venv\Scripts\python.exe scripts/remote.py status --host 25.9.106.39 --user bl1tz2200
```

Первая команда показывает всю очередь; `--json` добавляет полную историю.
Вторая открывает панель текущего опыта. Ctrl+C закрывает только просмотр.
`completed` и `11/11` подтверждают окончание всех обучений и подготовки результата;
`completed_with_errors` означает, что нужно прочитать список неудачных опытов.
Итоги: `Q:\AVITOCUP\experiments\MLP-SUITE-001\report.json`;
состояние: `status.json`; каждый опыт имеет собственные логи, веса и историю.
