# Общий слой данных

`recsys_data` — общий вход для модельных веток. Он проверяет данные, сохраняет исходные сигналы и предоставляет целые ленты или таблицы кандидатов/истории. Версия формата: 1.

## Подготовка

```bash
.venv/bin/python -m pip install -r requirements-data.txt
.venv/bin/python -m recsys_data \
  --data data/initial_audit/competition \
  --output artifacts/prepared-v1 \
  --allow-missing-embeddings
```

Флаг `--allow-missing-embeddings` нужен для текущей локальной копии: матрицы train/test ещё не скачаны. Таблицы можно подготовить и читать, но запрос отсутствующих векторов завершится понятной ошибкой. Нельзя подменять недоступную матрицу нулями или матрицей другого split. После скачивания матрицы по исходному пути создайте новый экземпляр `PreparedSplit`, и чтение векторов станет доступно.

Без этого флага требуются все матрицы выбранных split. Можно выбрать отдельные части через `--splits val` и задать размер порции `--batch-size 512` в целых лентах. Существующий output не перезаписывается: для новой версии используйте новый каталог.

## Что сохраняется

Все исходные f1–f5, категории, ID, timestamp, эмбеддинг пользователя, индексы item-векторов и поля истории сохраняются без изменения значений. Порядок кандидатов, событий истории и повторные события сохраняются. Ничего не удаляется, не нормализуется дополнительно и не дополняется до общей длины.

Каталог каждого split содержит:

- `features/`: исходные входы без target/pos и служебные маски/размеры;
- `labels/`: feed_id и исходный массив target, только train/val;
- `diagnostics/`: feed_id и исходный массив pos, только train.

История и user-вектор хранятся один раз на ленту. Матрицы item-векторов не копируются: загрузчик читает исходную memmap своего split. Векторы на диске остаются int8, выбранные строки выдаются float32 без L2-нормализации.

Новые поля features:

| Поле | Значение |
| --- | --- |
| `candidate_count` | Число кандидатов в ленте |
| `history_length` | Число доступных событий истории |
| `candidate_embedding_present` | Массив bool: индекс кандидата >= 0 |
| `history_embedding_present` | Массив bool: индекс события >= 0 |
| `user_embedding_is_zero` | Все 128 компонент user-вектора равны нулю; не утверждение о причине |
| `history_is_empty` | Длина истории равна нулю |

`True` в `*_embedding_present` означает, что вектор указан в исходном датасете. Наличие его матрицы на локальном диске отражается отдельно в manifest. Маска не становится False лишь потому, что файл ещё не скачан.

## Чтение в модельной ветке

Запускайте Python из корня репозитория:

```python
from recsys_data import PreparedSplit

validation = PreparedSplit("artifacts/prepared-v1", "val")
for batch in validation.iter_batches(batch_size=128, include_labels=True):
    candidate_rows = batch.candidate_table(include_target=True)
    group_sizes = batch.candidate_counts
    group_offsets = batch.candidate_offsets
    history_rows = batch.history_table()
    history_offsets = batch.history_offsets
    user_vectors = batch.user_vectors()  # float32 [feeds, 128]
    candidate_vectors, candidate_present = batch.candidate_vectors()
    history_vectors, history_present = batch.history_vectors()
    # Модельная обработка — в своей ветке.
```

`batch.features` остаётся Arrow-таблицей целых лент с вложенными списками. `candidate_table()` совместно разворачивает только поля кандидатов и сохраняет непрерывные группы; история не размножается на кандидатов. `candidate_index` — локальный индекс для согласования/восстановления порядка. В `history_table()` `history_index=0` соответствует новейшему событию; повторные item_id остаются на своих местах.

Без `include_labels=True` метки не читаются. `candidate_table()` по умолчанию не включает target даже у батча с загруженными метками. Для чтения pos нужен отдельный `include_diagnostics=True` у train. У test нельзя запросить метки, у val/test — исходные позиции.

Не передавайте все столбцы таблицы в модель автоматически. Feed_id, item_id, candidate_index, timestamp и embedding_idx — ключи или метаданные; способы использования ID и времени выбираются отдельно. Индекс в матрице не является числовым признаком объявления. Случайный индекс кандидата не является исходной позицией показа. Для входов используйте явный список признаков своей модели.

## Проверки и воспроизводимость

Подготовка отклоняет неожиданную схему/тип, null, неконечные f1–f5, некорректные длины массивов, недопустимые коды, индексы вне `[-1, N)`, небинарные метки, ленты без положительных меток, повторные кандидаты и повторные feed_id внутри/между выбранными split. При ошибке финальный каталог не создаётся; исходные файлы не изменяются.

Никаких значений не исправляется молча. При обнаружении новой особенности данных сначала меняется согласованная схема/политика, затем версия формата или подготовки.

Текущий `artifacts/prepared-v1` подготовлен и проверен: 67 610 лент, 6 220 289 кандидатов, 12 024 445 событий истории. Все исходные колонки 132 файлов точно восстановлены из подготовленного представления и сопоставлены с оригиналами. Отчёт: `reports/preparation_v1.json`. Train содержит только 4/512 исходных файлов; val/test полные. Это проверка сохранности и корректности, а не измерение модельного качества.

`manifest.json` фиксирует список и SHA-256 исходных Parquet, metadata векторов, версии библиотек и кода, числа объектов, доступность матриц. Если рядом с исходными данными есть `archive_manifest.json`, отмечается полное/частичное покрытие файлов официального архива. Без такого оглавления полнота неизвестна (`null`). Текущий train — подвыборка, а не полный обучающий датасет.

Пути к исходным матрицам относительные к подготовленному каталогу: рабочую папку можно переносить вместе с сохранением структуры. SHA-256 больших memmap при подготовке повторно не считается; контроль источника опирается на исходную проверку ZIP/аудит. Повторная подготовка нужна при замене исходных таблиц или матриц.

## Что остаётся модельным веткам

Масштабирование и imputation, кодирование категорий/ID, L2-нормализация, сходства и взаимодействия, агрегаты истории и ленты, обрезка истории, padding, отрицательный сэмплинг, веса и функции потерь. Обучаемые преобразования строятся на train; модельные признаки сравниваются по общему протоколу из PLAN.md.

```bash
.venv/bin/python -m unittest discover -s tests -v
```


## Загрузка train-эмбеддингов с восстановлением

```bash
python3 scripts/inspect_remote_zip.py --resume   --extract competition/train/item_embeddings/data.memmap
```

Сжатые блоки кэшируются в `data/initial_audit/.http-cache/` (до примерно 8,54 ГБ дополнительно); повторы после сетевых ошибок выполняются автоматически. Прогресс показывается каждые 5 секунд. Если старый запуск сохранил только распакованный префикс без кэша, первый восстановительный запуск повторно прочитает сжатый поток, проверит префикс и допишет хвост. При последующих перезапусках уже сохранённые сжатые блоки читаются из кэша. Не запускайте два загрузчика одновременно для одного файла.

Дождитесь сообщения `CRC verified` и успешного завершения процесса; итоговый размер train-матрицы — 10 439 416 832 байта. Без `--resume` существующие файлы не перезаписываются. Неполный файл не является доступной матрицей для обучения.
