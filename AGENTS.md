# Repository Guidelines

## Область работы и протокол

- Работать в `MLP`, `main` не менять. Читать `PLAN.md` и `experiments.md`. Роли У1/У2 и график отменены владельцем; протокол валидации сохраняется.

- Перед любым push или другой публикацией изменений в GitHub сначала показать владельцу локальный diff и дождаться его явного одобрения. Это прямое требование владельца проекта.
- Новые гипотезы и результаты, включая неудачные запуски, записывать в `experiments.md`. Не выдавать предполагаемые результаты за измеренные.
- Не закреплять конкретную архитектуру за участником. Сравнивать подходящие методы на общей валидации по правилам `PLAN.md`.
- Не добавлять в Git датасеты, веса моделей, секреты и большие артефакты запусков. Сохранять конфигурации, команды, метрики и ссылки на артефакты.

## Структура и команды

- `recsys_data/` — данные; `mlp/` — модель/обучение; `training_logs/` — события/панель; `scripts/` — управление; `tests/` — синтетические unittest.
- Проверка: `python -m unittest discover -s tests -v`. Соблюдать четыре пробела, `snake_case`, явные контракты и существующий Python-стиль. Данные не скачивать для тестов.
- Мониторинг сервера: `python scripts/remote.py status --host 25.9.106.39 --user bl1tz2200`; `--once` даёт один снимок, `--json` — машинный вывод. Ctrl+C останавливает только просмотр.
- Локальная очередь: `python scripts/local_ablation.py status --directory ../local-experiments/EXP-016-local-r01`. Завершение подтверждает `completed` вместе с итоговым `report.json`, а не окончание отдельной эпохи.

## Данные, изоляция и ресурсы

- Датасет зафиксирован: таблицы, кандидатов, метки и prepared-версии не менять. Серверный проект: `Q:/AVITOCUP/AvitoTech_ML_Cup`; данные: `Q:/AVITOCUP/competition`, `artifacts/prepared-full-v2`. Запуск на E: удалён.
- Каждый опыт получает новый ID, отдельный output и зафиксированный код. Для параллельных работ использовать отдельные worktree/снимки и окружения; общие входы доступны только для чтения. Запущенные процессы должны переживать закрытие CLI/SSH. Сервер не выключать и не перезагружать.
- Лимит нового MLP — 2 часа, если владелец не указал другой; это не ETA. Итоговая оценка отдельно. `--resume` сохраняет оптимизатор, RNG, курсор и бюджет; `--init-from` загружает только веса в новый опыт.
- После подтверждения первых шагов автономного обучения не ждать его окончания без отдельной просьбы.

## Качество и ручная отправка

- Метрика — полный NDCG с равным весом лент. Checkpoint выбирать по selection; поздний control не использовать для подбора параметров. Менять один фактор, сохранять контрольный вариант.
- Гипотезы, сбои, реальные результаты и версии записывать в `experiments.md`; измерения отделять от предположений. Онлайн-score, сообщённый владельцем, помечать как пользовательский отчёт.
- Предсказания строить из выбранного checkpoint. Перед ручной отправкой проверить Parquet через `scripts/validate_submission.py`: типы int32/int32/float32, конечность, уникальность и точное покрытие шаблона, SHA-256. Сначала дать владельцу ссылку на готовый файл.
- Подготовка файла не разрешает отправку на сайт. Нужна отдельная прямая просьба; учитывать уже совершённые ручные отправки и не дублировать их автоматически.
